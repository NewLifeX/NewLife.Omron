# NewLife.Omron 架构设计文档

## 1. 概述

NewLife.Omron 是一个纯 .NET 实现的欧姆龙 PLC 通信协议库，支持 FINS/TCP、FINS/UDP、HostLink 三种协议。本文档详细描述系统架构、设计原则、核心组件和扩展机制。

### 1.1 设计目标

| 目标 | 说明 |
|------|------|
| **零依赖** | 核心协议层仅依赖 .NET BCL，无第三方依赖 |
| **高性能** | 字节序转换、对象池、线程安全锁优化 |
| **易扩展** | 协议层、驱动层分离，便于新增协议或适配其他 IoT 平台 |
| **多框架** | 支持 net45/net461/netstandard2.0/netstandard2.1，兼容旧项目 |
| **异步优先** | 全部 API 提供同步+异步版本，库内部使用 ConfigureAwait(false) |
| **测试友好** | 提供 FinsServer 模拟服务器，支持单元测试和集成测试 |

### 1.2 技术栈

| 层次 | 技术 |
|------|------|
| 协议层 | .NET BCL (Socket/UdpClient/TcpClient/TcpListener/Stream) |
| 驱动层 | NewLife.IoT (DriverBase/INode/IDriverParameter) |
| 测试框架 | xUnit 2.9.3 + Microsoft.NET.Test.Sdk 17.12.0 |
| 日志 | NewLife.Log (XTrace) |

## 3. 核心组件设计

### 3.1 协议层

#### 3.1.1 FinsClient (FINS/TCP)

**职责**：
- TCP 连接管理（连接/断开/自动重连）
- FINS/TCP 握手（获取客户端/服务端节点地址）
- FINS 帧封装/解封装（TCP 头部 + FINS 帧）
- 同步/异步 API 实现

**关键实现**：
```csharp
// TCP 头部结构（16字节）
[FINS(4)] + [Length(4)] + [Command(4)] + [ErrorCode(4)] + [FinsFrame(N)]

// 握手流程
1. 客户端发送: 46 49 4E 53 00 00 00 0C 00 00 00 00 00 00 00 00
2. 服务端响应: 46 49 4E 53 00 00 00 10 00 00 00 01 00 00 00 00 [ClientNode] [ServerNode] 00 00

// 自动重连机制
- AutoReconnect 属性（默认 true）
- MaxReconnectRetries 属性（默认 3 次）
- 退避策略：1s → 2s → 3s
- 错误识别：IOException / SocketException / TimeoutException
```

**线程安全**：
- 同步方法：使用 `lock(_lock)` 串行化访问
- 异步方法：使用 `SemaphoreSlim(1,1)` 异步锁

#### 3.1.2 FinsUdpClient (FINS/UDP)

**职责**：
- UDP 通信管理（无需握手）
- 直接发送/接收 FINS 帧（无 TCP 头部）
- 节点地址自动推导（从 IP 地址最后一段）

**关键实现**：
```csharp
// UDP 帧结构（无 TCP 头部）
[FinsFrame(N)] = [FinsHeader(10)] + [CommandData(N)]

// 节点地址推导
- DestinationNodeAddress: 从构造函数的 ipAddress 参数解析（192.168.1.10 → 10）
- SourceNodeAddress: 从 UdpClient 本地端点 IP 解析
```

**适用场景**：
- 快速轮询（无 TCP 握手开销）
- 广播通信（FINS 支持）
- 无需可靠传输的场景

#### 3.1.3 HostLinkClient (串口/TCP)

**职责**：
- HostLink C-mode 协议实现
- 串口/TCP 双传输支持（基于 Stream 抽象）
- FCS 异或校验
- FINS 网关命令（通过 HostLink 发送 FINS 命令）

**关键实现**：
```csharp
// C-mode 帧格式
@[UU][CC][DATA][FCS]*[CR]
- @: 起始符
- UU: 单元号（00-31）
- CC: 命令码（RD/WD/RR/WR 等）
- DATA: ASCII 十六进制数据
- FCS: 异或校验（UU 到 DATA 的所有字符）
- *: 分隔符
- CR: 结束符

// 支持命令
- RD/WD: DM 区读写
- RR/WR: CIO 区读写
- RH/WH: HR 区读写
- RJ/WJ: AR 区读写
- RC/WC: TIM/CNT 读写
- RE/WE: EM 区读写
- SC: CPU 状态读取/切换
- TS: 通信测试（回环）
- FA: FINS 网关（发送任意 FINS 命令）
```

**传输适配**：
```csharp
// 串口模式
var serial = new SerialPort("COM1", 9600, Parity.Even, 7, StopBits.Two);
serial.Open();
using var client = new HostLinkClient(serial.BaseStream);

// TCP 模式（串口服务器）
var tcp = new TcpClient("192.168.1.100", 4001);
using var client = new HostLinkClient(tcp.GetStream());
```

#### 3.1.4 OmronClientBase (抽象基类)

**职责**：
- 统一类型化读写 API（避免三个客户端重复代码）
- ByteTransform 字节序转换封装
- 超时配置统一管理

**设计模式**：模板方法模式
```csharp
// 抽象方法（子类实现）
public abstract Byte[] Read(String address, UInt16 length);
public abstract void Write(String address, Byte[] data);

// 模板方法（基类实现）
public Int32 ReadInt32(String address)
{
    var data = Read(address, 2); // 调用子类方法
    return Transform.TransInt32(data, 0);
}
```

#### 3.2.2 FinsAddress (地址解析)

**职责**：
- 解析地址字符串（D100、CIO200.5、EM0:100）
- 区分字访问/位访问
- 存储区代码转换（字/位代码）
- 支持多 Bank 扩展存储器（EM0~EM3）

**解析规则**：
```csharp
// 格式: [前缀][地址][.位偏移]
D100        → MemoryType=DM, Address=100, BitOffset=0
CIO200.5    → MemoryType=CIO, Address=200, BitOffset=5
EM0:100     → MemoryType=EM0, Address=100
TIM5        → MemoryType=TIM, Address=5
CNT10       → MemoryType=CNT, Address=10
IR0         → MemoryType=IR, Address=0
DR0         → MemoryType=DR, Address=0

// Bank 编号映射（EM0~EM3）
EM0: → 0xA0/0x20
EM1: → 0xA1/0x21
EM2: → 0xA2/0x22
EM3: → 0xA3/0x23
```

**字段**：
```csharp
public MemoryArea MemoryType { get; set; } // 存储区类型
public UInt16 Address { get; set; } // 地址
public Byte BitOffset { get; set; } // 位偏移（0-15）
public Boolean IsBit { get; set; } // 是否为位访问
```

#### 3.2.3 ByteTransform (字节序转换)

**职责**：
- 多字节数据类型与字节数组互转
- 支持四种字节序（ABCD/BADC/CDAB/DCBA）
- 字符串编码/解码（ASCII）

**字节序说明**：
```csharp
// 以 Int32 值 0x12345678 为例
ABCD (标准大端)   : [12] [34] [56] [78]
BADC (字内交换)   : [34] [12] [78] [56]
CDAB (欧姆龙默认) : [56] [78] [12] [34] ← FinsClient/FinsUdpClient/HostLinkClient 默认
DCBA (标准小端)   : [78] [56] [34] [12]

// 为什么欧姆龙使用 CDAB？
欧姆龙 PLC 按字（16位）为单位存储数据，高字在前，但字内是小端（低字节在前）
32位整数 0x12345678 存储为：
  DM100 = 0x5678 (低字) → 内存 [78 56]
  DM101 = 0x1234 (高字) → 内存 [34 12]
  连续读取 → [78 56 34 12] → 需要 CDAB 转换为 0x12345678
```

**API**：
```csharp
// 字节 → 类型
Int16 TransInt16(Byte[] data, Int32 offset)
UInt16 TransUInt16(Byte[] data, Int32 offset)
Int32 TransInt32(Byte[] data, Int32 offset)
UInt32 TransUInt32(Byte[] data, Int32 offset)
Int64 TransInt64(Byte[] data, Int32 offset)
UInt64 TransUInt64(Byte[] data, Int32 offset)
Single TransSingle(Byte[] data, Int32 offset)
Double TransDouble(Byte[] data, Int32 offset)
String TransString(Byte[] data, Int32 offset, Int32 length)

// 类型 → 字节
Byte[] TransByte(Int16 value)
Byte[] TransByte(UInt16 value)
Byte[] TransByte(Int32 value)
Byte[] TransByte(UInt32 value)
Byte[] TransByte(Int64 value)
Byte[] TransByte(UInt64 value)
Byte[] TransByte(Single value)
Byte[] TransByte(Double value)
Byte[] TransByte(String value)
```

### 3.4 IoT 驱动层

#### 3.4.1 OmronDriver (驱动实现)

**职责**：
- 实现 NewLife.IoT 标准驱动接口（DriverBase）
- 管理多个 OmronNode 节点
- 共享底层 FinsClient 连接（引用计数）
- 处理驱动级别的配置和生命周期

**关键实现**：
```csharp
[Driver("OmronPLC")]
public class OmronDriver : DriverBase
{
    // 驱动级别配置
    protected override IDriverParameter CreateParameter() => new OmronParameter();

    // 设备连接（多节点共享）
    protected override Boolean Open(IDevice device, IDriverParameter parameter)
    {
        var para = parameter as OmronParameter;
        var client = GetOrCreateClient(para.Address); // 引用计数
        device.Tag = client;
        return true;
    }

    // 设备断开（引用计数-1）
    protected override void Close(IDevice device)
    {
        var client = device.Tag as FinsClient;
        ReleaseClient(client);
    }

    // 读取数据
    protected override Object Read(INode node, IDriverParameter parameter)
    {
        var client = node.Device.Tag as FinsClient;
        var addr = node.Address.Split(':')[0]; // 支持 D100:Int32 格式
        return client.Read(addr, 2);
    }

    // 写入数据（自动类型转换）
    protected override void Write(INode node, Object value)
    {
        var client = node.Device.Tag as FinsClient;
        var addr = node.Address.Split(':')[0];
        
        if (value is Int16 i16) client.WriteInt16(addr, i16);
        else if (value is Int32 i32) client.WriteInt32(addr, i32);
        else if (value is Single f) client.WriteFloat(addr, f);
        // ... 其他类型
    }
}
```

## 4. 设计模式应用

### 4.1 模板方法模式 (Template Method)

**应用位置**：OmronClientBase

**目的**：统一三个客户端的类型化读写 API，避免代码重复

**实现**：
```csharp
// 抽象基类定义抽象方法（子类实现）
public abstract Byte[] Read(String address, UInt16 length);

// 基类定义模板方法（调用抽象方法）
public Int32 ReadInt32(String address)
{
    var data = Read(address, 2); // 调用子类实现
```

### 4.2 策略模式 (Strategy)

**应用位置**：ByteTransform 字节序转换

**目的**：运行时切换不同字节序策略（ABCD/BADC/CDAB/DCBA）

**实现**：
```csharp
public class ByteTransform
{
    public ByteOrder ByteOrder { get; set; } // 策略选择器
    
    public Int32 TransInt32(Byte[] data, Int32 offset)
    {
        switch (ByteOrder)
        {
            case ByteOrder.ABCD: return BitConverter.ToInt32([data[offset+3], data[offset+2], data[offset+1], data[offset]], 0);
            case ByteOrder.BADC: return BitConverter.ToInt32([data[offset+2], data[offset+3], data[offset], data[offset+1]], 0);
            case ByteOrder.CDAB: return BitConverter.ToInt32([data[offset+1], data[offset], data[offset+3], data[offset+2]], 0);
            case ByteOrder.DCBA: return BitConverter.ToInt32([data[offset], data[offset+1], data[offset+2], data[offset+3]], 0);
        }
    }
}
```

### 4.5 单例模式 (Singleton)

**应用位置**：OmronDriver 的连接池管理

**目的**：多个 OmronNode 共享同一个 FinsClient 连接

**实现**：
```csharp
private readonly Dictionary<String, (FinsClient Client, Int32 RefCount)> _clients = new();

private FinsClient GetOrCreateClient(String address)
{
    lock (_lock)
    {
        if (_clients.TryGetValue(address, out var entry))
        {
            entry.RefCount++;
            _clients[address] = entry;
            return entry.Client;
        }
        
        var client = new FinsClient(address.Split(':')[0], Int32.Parse(address.Split(':')[1]));
        client.Connect();
        _clients[address] = (client, 1);
        return client;
    }
}

private void ReleaseClient(FinsClient client)
{
    lock (_lock)
    {
        foreach (var kvp in _clients)
        {
            if (kvp.Value.Client == client)
            {
                var newCount = kvp.Value.RefCount - 1;
                if (newCount == 0)
                {
                    client.Dispose();
                    _clients.Remove(kvp.Key);
                }
                else
                {
                    _clients[kvp.Key] = (client, newCount);
                }
                break;
            }
        }
    }
}
```

## 5. 性能优化

### 5.1 线程安全策略

| 客户端 | 同步方法 | 异步方法 | 说明 |
|--------|----------|----------|------|
| FinsClient | `lock(_lock)` | `SemaphoreSlim(1,1)` | 避免死锁，异步方法不使用 lock |
| FinsUdpClient | `lock(_lock)` | `SemaphoreSlim(1,1)` | 同上 |
| HostLinkClient | `lock(_lock)` | `SemaphoreSlim(1,1)` | 同上 |
| FinsServer | `lock(_lock)` | - | 服务端仅同步操作 |

### 5.2 内存优化

| 策略 | 应用位置 | 说明 |
|------|----------|------|
| **栈分配** | ByteTransform | 使用 `stackalloc` 分配小数组（<= 8 字节） |
| **数组共享** | FinsMessage | 复用缓冲区构建帧 |
| **延迟分配** | FinsServer 存储区 | 按需创建存储区数组 |
| **集合表达式** | 全局 | 使用 `[]` 初始化集合减少分配 |

### 5.3 批量读取优化

**问题**：逐个地址读取会产生大量网络往返

**解决**：BatchRead 方法自动合并相邻地址

**算法**：
```csharp
1. 解析所有地址，按存储区类型+地址排序
2. 识别连续/重叠地址段
3. 合并为单个大读取
4. 拆分结果返回到原始地址顺序

示例：
输入: [D100(2字), D102(2字), D105(3字)]
↓ 排序（已有序）
↓ 合并: D100~D108 共 8 字
↓ 单次读取 Read("D100", 8)
↓ 拆分: [D100(4字节), D102(4字节), D105(6字节)]
```

### 5.4 自动重连优化

**退避策略**：避免快速重连导致服务端压力

```csharp
// 重试次数 → 等待时间
1 → 1秒
2 → 2秒
3 → 3秒
```

**错误识别**：仅特定异常触发重连
- IOException（网络中断）
- SocketException（连接重置）
- TimeoutException（超时）

```csharp
    var value = client.ReadInt32("D100");
}
catch (InvalidOperationException ex) when (ex.Message.Contains("EndCode"))
{
    // FINS 协议错误（PLC 返回错误码）
    _log.Error($"PLC返回错误: {ex.Message}");
}
catch (TimeoutException ex)
{
    // 通信超时
    _log.Warning($"通信超时: {ex.Message}");
}
catch (SocketException ex)
{
    // 网络故障
    _log.Error($"网络故障: {ex.Message}");
}
```

**避免**：
```csharp
// ? 吞噬所有异常
try
{
    var value = client.ReadInt32("D100");
}
catch
{
    // 无法判断错误类型，无法采取针对性措施
}
```

### 14.4 批量操作

**推荐**：
```csharp
// ? 使用 BatchRead 减少通信次数
var addresses = new[] { "D100", "D102", "D105", "D110" };
var lengths = new UInt16[] { 2, 2, 3, 2 };
var results = client.BatchRead(addresses, lengths);
// 内部合并为 1-2 次通信
```

**避免**：
```csharp
// ? 逐个读取（4 次通信）
var d100 = client.Read("D100", 2);
var d102 = client.Read("D102", 2);
var d105 = client.Read("D105", 3);
var d110 = client.Read("D110", 2);
```

### 14.5 字节序配置

**推荐**：
```csharp
// ? 使用欧姆龙默认字节序（CDAB）
var client = new FinsClient("192.168.1.10", 9600);
// client.ByteOrder = ByteOrder.CDAB; // 默认值，无需设置

// 如需其他字节序，明确设置
client.ByteOrder = ByteOrder.ABCD; // 标准大端
```

**原因**：欧姆龙 PLC 存储多字节数据时按字（16位）为单位，高字在前，但字内是小端，CDAB 字节序匹配这种存储方式。

## 15. 常见问题

### 15.1 连接失败

**现象**：`Connect()` 抛出 SocketException

**排查**：
1. 检查 IP 地址和端口是否正确
2. 检查网络连通性（ping PLC IP）
3. 检查 PLC FINS/TCP 服务是否启用
4. 检查防火墙规则
5. 检查 PLC 的 FINS 节点表配置

### 15.2 读取数据异常

**现象**：`Read()` 抛出 InvalidOperationException，提示 EndCode 错误

**排查**：
1. 检查地址是否超出 PLC 存储区范围
2. 检查存储区类型是否正确（DM/CIO/HR 等）
3. 检查 PLC 当前模式（Program 模式可能限制访问）
4. 检查 PLC 访问权限（是否被其他设备占用）

### 15.3 数据值不正确

**现象**：读取的值与 PLC 实际值不符

**排查**：
1. 检查字节序配置（`ByteOrder` 属性）
2. 使用 ReadInt16/ReadUInt16 而非 ReadInt32（数据类型匹配）
3. 检查地址偏移（D100 vs D101）
4. 使用十六进制查看原始字节（`Read()` 方法）

### 15.4 异步方法死锁

**现象**：调用 `ReadAsync()` 时程序卡死

**原因**：WinForms/WPF 应用中同步等待异步方法（`.Result` / `.Wait()`）导致死锁

**解决**：
```csharp
// ? 死锁
var data = client.ReadAsync("D100", 2).Result;

// ? 方案1: 全链路异步
var data = await client.ReadAsync("D100", 2);

// ? 方案2: 使用同步方法
var data = client.Read("D100", 2);
```

### 15.5 FinsServer 无法启动

**现象**：`Start()` 抛出 SocketException（端口占用）

**解决**：
```csharp
// ? 使用随机端口
server.Start(0);
Console.WriteLine($"服务端口: {server.Port}");
```
