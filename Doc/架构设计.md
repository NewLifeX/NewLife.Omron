## 1. 设计原则与技术栈

### 1.1 核心设计原则

| 原则 | 说明 |
|------|------|
| **零依赖** | 协议层仅依赖 .NET BCL（Socket/UdpClient/TcpClient/Stream），零第三方运行时依赖 |
| **分层职责** | 传输层→协议层→类型层→驱动层，每层职责单一，向上依赖，可独立替换 |
| **高性能** | 字节序转换、地址解析缓存化；批量读取合并相邻地址，减少通信次数 |
| **线程安全** | 同步路径用 `lock`，异步路径用 `SemaphoreSlim(1,1)`，两者不混用 |
| **可测试** | FinsServer 模拟服务器实现完整 FINS/TCP 栈，全部测试在内存回路运行 |
| **异步兼容** | 库内部异步调用均使用 `ConfigureAwait(false)`，避免 UI/ASP.NET 上下文死锁 |

### 1.2 技术栈

| 层次 | 技术 |
|------|------|
| 协议层 | .NET BCL：`TcpClient`、`UdpClient`、`NetworkStream`、`Socket` |
| 驱动层 | `NewLife.IoT`：`DriverBase`、`INode`、`IDriverParameter` |
| 测试框架 | `xUnit 2.9.3`、`Microsoft.NET.Test.Sdk 17.12.0` |
| 日志 | `NewLife.Core`：`XTrace`（通过 NewLife.IoT 传递） |
| 构建 | `Microsoft.SourceLink.GitHub`（仅构建期，无运行时依赖） |

## 3. 协议层设计

### 3.1 FinsClient（FINS/TCP）

**文件**：`Protocols/FinsClient.cs` + `Protocols/FinsClient.Async.cs`

**职责**：管理 TCP 长连接生命周期，实现 FINS/TCP 握手协议，封装所有 27 种 FINS 命令的发送/接收逻辑。

#### 3.1.1 TCP 帧格式

FINS/TCP 在原始 FINS 帧外层增加了一个 16 字节的 TCP 头：

```
TCP 帧 = [FINS标识(4字节)] + [数据长度(4字节)] + [命令码(4字节)] + [错误码(4字节)] + [FINS帧(N字节)]

FINS标识：0x46 0x49 0x4E 0x53  ("FINS")
数据长度：后续字节总长（命令码4 + 错误码4 + FINS帧N）
命令码：  0x00000000 = FINS数据帧
         0x00000001 = 握手响应
```

#### 3.1.2 握手协议

连接建立后，客户端必须先完成节点地址握手才能发送 FINS 命令：

```
1. 客户端发送握手请求（12字节）：
   FINS(4) + Length=0C(4) + Command=0000(4) + ClientNode=00(4)

2. 服务端回复握手响应（24字节）：
   FINS(4) + Length=10(4) + Command=0001(4) + ErrorCode(4) + ClientNode(1) + ServerNode(1) + ...

3. 客户端保存 ClientNode 和 ServerNode，填入后续 FINS 帧头部路由字段
```

#### 3.1.3 自动重连机制

```
连接断开检测条件：IOException / SocketException / TimeoutException

重试策略：
  第1次：等待 1s
  第2次：等待 2s
  第3次：等待 3s
  超过 MaxReconnectRetries (默认3) 次后，抛出异常给调用方

属性控制：
  AutoReconnect（bool，默认 true）：是否开启自动重连
  MaxReconnectRetries（int，默认 3）：最大重试次数
```

#### 3.1.4 线程安全设计

```csharp
// 同步 API：使用 lock 互斥
private readonly Object _lock = new();

// 异步 API：使用 SemaphoreSlim 异步互斥
private readonly SemaphoreSlim _semaphore = new(1, 1);
```

两种机制分别用于同步和异步调用路径，不能混用（避免死锁）。

### 3.2 FinsUdpClient（FINS/UDP）

**文件**：`Protocols/FinsUdpClient.cs` + `Protocols/FinsUdpClient.Async.cs`

**职责**：实现基于 UDP 的 FINS 通信，无连接、无握手、直接发送/接收 FINS 帧。

#### 3.2.1 UDP 帧格式

FINS/UDP 使用原始 FINS 帧，无 TCP 头：

```
UDP 帧 = [FinsHeader(10字节)] + [命令数据(N字节)]
```

#### 3.2.2 节点地址推导

FINS/UDP 不通过握手获取节点地址，使用约定推导：

```
目标节点（DA1）= IP 地址最后一个八位组
  示例：192.168.1.10  →  DA1 = 10

源节点（SA1）= 客户端本机 IP 最后一个八位组
  示例：UdpClient 绑定的本地 IP = 192.168.1.20  →  SA1 = 20
```

#### 3.2.3 适用场景

- 高频数据采集（无需建立和维护 TCP 长连接）
- FINS 广播（发往网段广播地址）
- 对网络可靠性要求不高的场景（UDP 不保证送达）

### 3.3 HostLinkClient（HostLink C-mode）

**文件**：`Protocols/HostLinkClient.cs` + `Protocols/HostLinkClient.Async.cs`

**职责**：实现欧姆龙 HostLink C-mode 协议，支持串口和 TCP（串口服务器）两种传输方式。

#### 3.3.1 C-mode 帧格式

```
帧格式：  @  UU  CC  DATA  FCS  *  CR
示例：    @  00  RD  0000000A  XX  *  <CR>

字段说明：
  @     ：帧起始符（固定）
  UU    ：单元号（00-31，ASCII 十六进制，最多 32 个设备）
  CC    ：命令头码（如 RD/WD/RR/WR/RH/WH 等）
  DATA  ：命令参数（ASCII 十六进制编码）
  FCS   ：帧校验序列（从 UU 到 DATA 末尾的 XOR 累计，2字节 ASCII 十六进制）
  *     ：帧结束符
  CR    ：回车符（0x0D）
```

#### 3.3.2 FCS 计算

```csharp
// FCS = 从 UU 到 DATA 末尾（含）所有字符的异或累加
var fcs = 0;
foreach (var b in frame[1..^1])  // 跳过 @ 和 *CR
    fcs ^= b;
// 结果转为 2 字节大写十六进制字符串
```

#### 3.3.3 支持的命令头码

| 命令头码 | 操作 | 存储区 |
|---------|------|--------|
| RD / WD | 读 / 写 | DM（数据存储区） |
| RR / WR | 读 / 写 | CIO（Core I/O 区） |
| RH / WH | 读 / 写 | HR（保持区） |
| RJ / WJ | 读 / 写 | AR（辅助区） |
| RC / WC | 读 / 写 | TIM/CNT（定时/计数器） |
| RE / WE | 读 / 写 | EM（扩展存储区） |
| SC      | 读取   | CPU 状态 |
| TS      | 测试   | 通信测试（回环） |
| FA      | FINS 封装 | 透传 FINS 帧（FINS 网关） |

#### 3.3.4 双模式传输

```csharp
// 串口模式
var serial = new SerialPort("COM1", 9600, Parity.Even, 7, StopBits.Two);
serial.Open();
using var client = new HostLinkClient(serial.BaseStream);

// TCP 模式（串口服务器）
var tcp = new TcpClient("192.168.1.100", 4001);
using var client = new HostLinkClient(tcp.GetStream());
```

## 4. 公共基础组件

### 4.1 OmronClientBase（抽象基类）

**文件**：`Protocols/OmronClientBase.cs`

三个具体客户端（`FinsClient`、`FinsUdpClient`、`HostLinkClient`）都继承自该抽象基类。

```
职责：
  1. 持有 ByteTransform 实例（字节序转换）
  2. 提供全部类型化读写方法（共 22 对同步+异步方法）
  3. 定义抽象方法 Read()/Write()/ReadBit()/WriteBit() 由子类实现
  4. 统一属性：ByteOrder、ReceiveTimeout、Host、Port
```

类型化 API 的实现模式：

```csharp
// 所有类型方法都是对 Read/Write 原始字节的包装
public Int32 ReadInt32(String address)
{
    var data = Read(address, 2);     // 读取 2 个字（4 字节）
    return Transform.TransInt32(data, 0);  // 按字节序转换
}
```

### 4.2 ByteTransform（字节序转换器）

**文件**：`Protocols/ByteTransform.cs`

负责将原始字节数组与各种数值类型相互转换，支持四种字节序。

```
字节序映射（以 Int32 为例，字节标记为 A B C D）：
  ABCD：[A][B][C][D]  →  大端序（PLC 网络字节序）
  BADC：[B][A][D][C]  →  字内字节交换
  CDAB：[C][D][A][B]  →  双字交换（欧姆龙 PLC 默认格式）
  DCBA：[D][C][B][A]  →  小端序（x86 本机字节序）

支持类型：Int16/UInt16/Int32/UInt32/Int64/UInt64/Single/Double/String/Boolean/Byte[]
```

### 4.3 FinsMessage（FINS 消息构建/解析）

**文件**：`Protocols/FinsMessage.cs`

负责构建各种 FINS 命令的请求帧，以及解析响应帧。

```
主要方法：
  BuildReadRequest(address, length)    → 构建存储区读取请求
  BuildWriteRequest(address, data)     → 构建存储区写入请求
  BuildBitReadRequest(address, count)  → 构建位读取请求
  BuildBitWriteRequest(address, bit)   → 构建位写入请求
  ParseResponse(bytes)                 → 解析响应帧
  IsSuccess(response)                  → 判断响应是否成功
  GetErrorMessage(endCode)             → 获取 38 种错误码的中文说明
```

### 4.4 FinsHeader（FINS 路由头）

**文件**：`Protocols/FinsHeader.cs`

FINS 帧的前 10 字节为路由头，包含源/目标节点地址等路由信息。

```
FINS 路由头（10 字节）：
  Byte 0: ICF  - 信息控制字段（命令/响应位）
  Byte 1: RSV  - 保留（0x00）
  Byte 2: GCT  - 网关计数（0x07）
  Byte 3: DNA  - 目标网络地址（0x00 = 本地）
  Byte 4: DA1  - 目标节点地址（PLC IP 最后一字节）
  Byte 5: DA2  - 目标单元号（0x00 = CPU）
  Byte 6: SNA  - 源网络地址（0x00 = 本地）
  Byte 7: SA1  - 源节点地址（客户端 IP 最后一字节）
  Byte 8: SA2  - 源单元号（0x00）
  Byte 9: SID  - 服务 ID（序列号，用于请求/响应配对）
```

### 4.5 FinsCommand（FINS 命令码常量）

**文件**：`Protocols/FinsCommand.cs`

以常量形式定义 FINS 协议中全部 27 种命令的 MRC（主请求码）和 SRC（子请求码）：

```csharp
// 命令码定义示例
public static readonly Byte[] MemoryAreaRead     = [0x01, 0x01];
public static readonly Byte[] MemoryAreaWrite    = [0x01, 0x02];
public static readonly Byte[] ControllerDataRead = [0x05, 0x01];
public static readonly Byte[] Run                = [0x04, 0x01];
// ...共 27 个命令定义
```

### 4.6 FinsAddress（地址解析）

**文件**：`Protocols/FinsAddress.cs`

将开发者友好的地址字符串（如 `D100`、`CIO50.5`、`EM0:200`）解析为 FINS 协议所需的三字节地址格式。

```
输入示例  →  输出（存储区代码 + 地址高位 + 地址低位 + 位偏移）：
  "D100"       →  [0x82, 0x00, 0x64, 0x00]  (DM 字地址 100)
  "CIO50.5"    →  [0x30, 0x00, 0x32, 0x05]  (CIO 位地址 50.5)
  "EM0:200"    →  [0xA0, 0x00, 0xC8, 0x00]  (EM Bank0 字地址 200)
  "TIM5"       →  [0x89, 0x00, 0x05, 0x00]  (定时器 5)

支持前缀（大小写不敏感）：
  DM/D，CIO/C，WR/W，HR/H，AR/A，EM/EM0~EM3，TIM，CNT，IR，DR
```

### 4.7 MemoryArea（存储区枚举）

**文件**：`Protocols/MemoryArea.cs`

定义所有存储区的字代码和位代码，并提供辅助方法（判断是否为位区、获取地址范围等）。

## 5. IoT 驱动层设计

### 5.1 整体结构

IoT 驱动层是协议层对上的适配层，实现 `NewLife.IoT` 定义的标准驱动接口，使本库可以接入 NewLife 生态（星尘分布式平台、IoTEdge 网关）。

```
OmronDriver（继承 DriverBase，[Driver("OmronPLC")]）
  ├── 持有：FinsClient _client（单例，所有节点共享）
  ├── 持有：Int32 _nodes（当前打开的节点计数，引用计数器）
  ├── Open(node, parameter)   → 创建 OmronNode，首次打开时建立连接
  ├── Close(node)             → 引用计数归零时断开连接
  ├── Read(node, points)      → 批量读取多点位，返回 Dictionary<String, Object>
  └── Write(node, point, val) → 写入单个点位

OmronNode（实现 INode）
  └── 持有设备地址（IP:Port）和设备配置引用

OmronParameter（实现 IDriverParameter）
  ├── Address：IP:Port（如 "192.168.1.10:9600"）
  ├── DA2：目标单元号（默认 0）
  └── DataFormat：字节序（"CDAB"/"ABCD"/"BADC"/"DCBA"）
```

### 5.2 引用计数共享连接

多个不同节点（`OmronNode`）可以共享同一个 PLC 连接（`FinsClient`），由驱动层的引用计数负责管理连接的生命周期：

```
Open 时：
  _nodes++
  if (_nodes == 1) → 创建 FinsClient 并连接

Close 时：
  _nodes--
  if (_nodes == 0) → 断开并释放 FinsClient
```

## 6. FinsServer 模拟服务器

**文件**：`Protocols/FinsServer.cs`

FinsServer 是一个完整的 FINS/TCP 服务端实现，用于开发调试和单元测试，无需真实 PLC 硬件。

### 6.1 内部结构

```
FinsServer
  ├── TcpListener（监听连接）
  ├── _memory：Byte[]（模拟存储区，20000 字 × 2 = 40000 字节）
  ├── _cpuModel：String（模拟 CPU 型号，如 "CJ2M-CPU31"）
  ├── _mode：CpuMode（模拟运行模式：Run/Monitor/Stop）
  ├── _clock：DateTime（模拟 PLC 时钟）
  └── _errorLog：List<Byte[]>（模拟错误日志）
```

### 6.2 支持的操作

- **握手**：正确响应客户端握手请求，分配节点地址
- **读写**：响应存储区读取/写入/填充/传送命令
- **CPU 控制**：模拟 PlcRun/PlcStop，切换 `_mode`
- **设备信息**：返回配置的 CPU 型号、版本
- **时钟**：支持读取/写入模拟时钟
- **错误日志**：支持读取和清除模拟错误日志

### 6.3 使用方式

```csharp
// 使用随机端口启动模拟服务器
using var server = new FinsServer();
server.CpuModel = "CJ2M-CPU31";
server.Start();           // 随机端口，避免并行测试冲突

// 预写入测试数据
server.WriteMemory(0x82, 100, new byte[] { 0x00, 0x0A }); // DM100 = 10

// 客户端连接并验证
using var client = new FinsClient("127.0.0.1", server.Port);
client.Connect();
var val = client.ReadInt16("D100");  // 返回 10
```

## 8. 需求文档功能模块对应关系

每个需求功能模块（P/M/C/T/B/F/S/D/E）都有对应的代码实现：

| 需求模块 | 关键类 / 文件 | 设计决策 |
|----------|---------------|----------|
| P-01 FINS/TCP | `FinsClient` | TCP + 16字节头；握手后保存节点地址 |
| P-02 FINS/UDP | `FinsUdpClient` | 无握手；节点地址从 IP 末段推导 |
| P-03 HostLink | `HostLinkClient` + `HostLinkMessage` | 统一接受 Stream，支持串口/TCP两种传输 |
| P-04 握手协议 | `FinsClient.Connect()` | 两步握手：发送12字节请求，解析24字节响应 |
| P-05 自动重连 | `FinsClient._reconnect` | 退避重试：1s/2s/3s，最大3次 |
| P-06 FA命令 | `HostLinkClient.SendFinsCommand()` | HostLink FA帧包装FINS帧，透传到PLC |
| P-07 异步API | `*.Async.cs` (partial) | 所有同步方法都有对应 Async，使用 SemaphoreSlim |
| M-01~M-13 存储区 | `MemoryArea` + `FinsAddress` | MemoryArea 枚举定义代码；FinsAddress 负责解析地址字符串 |
| C-01~C-27 FINS命令 | `FinsCommand` + `FinsMessage` + `FinsClient` | 命令码在 FinsCommand 定义；FinsMessage 构建帧；FinsClient 发送 |
| T-01~T-22 类型API | `OmronClientBase` | 全部类型方法通过 ByteTransform 对 Read/Write 原始字节做包装 |
| B-01~B-04 字节序 | `ByteTransform` | 4×6 共24种转换组合，全部有独立测试 |
| F-01 批量读取 | `FinsClient.MultipleRead()` | 命令 01:04，一次发送多个不连续地址 |
| F-07 时钟 | `FinsClient.ReadClock()` | BCD 编解码封装在 FinsMessage 内 |
| S-01~S-07 模拟服务器 | `FinsServer` | 独立 TcpListener，20000字存储区，响应全部27种命令 |
| D-01~D-05 驱动集成 | `OmronDriver` + `OmronNode` + `OmronParameter` | 引用计数共享连接；通过 [Driver] 属性自动注册 |
| E-01~E-04 多框架 | `NewLife.Omron.csproj` | `<TargetFrameworks>net45;net461;netstandard2.0;netstandard2.1</TargetFrameworks>` |
